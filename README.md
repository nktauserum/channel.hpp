### Принцип работы

Канал представляет собой совокупность отдельных очередей, каждая из которых привязывается к отдельному воркеру. Данные отправляются лишь в одну сторону: канал => рабочий процесс. Распределение задач между очередями достигается с помощью round-robin.

Очередь является обычным, но чуточку оптимизированным кольцевым буфером. Из оптимизаций можно отметить кэширование значений некоторых атомиков для более быстрого доступа к ним.

Для синхронизации состояния между потоками не используется никаких блокирующих операций, только атомарные операции. Опционально можно использовать futex во избежание busy spinning на непрерывном чтении пустой очереди.

### Почему не общая очередь для неограниченного количества воркеров?

Тогда атомики (минимум head и tail) превращаются в объекты с общим доступом, за которые конкурирует большое число потоков. Синхронизация начинает занимать сравнительно больше времени, имея шанс превратить канал в узкое место.
